# AI Coding 全过程记录

本文件是赛事说明要求的**独立重点材料**，记录本届首版从需求到验证与交付的 AI Coding 流程。仅记载实际完成的工作。开发所用 AI Coding 工具：**OpenAI Codex**。其具体用途如下。

## 1. 需求分析：人与 AI 的首次交互

参赛者向 Codex 提供赛事文字、截图及“Book to Course / 智讲 Agent”构想，提出先建立初始框架、编写并通过测试。Codex 首先检查仓库，确认只有 README 和许可证，无现成产品代码或测试。又检查本机 Python 3.13、Node、FFmpeg 可用性与中文系统语音；结果显示未安装系统 FFmpeg，但有 Windows 中文语音。

Codex 将赛事内容转成工程验收项：两项材料必须齐全；产品说明书必须说明产品、设计思路、设计过程、商业价值/创新性；AI Coding 工具名称、用途和完整交互过程须单列；引用他人程序须标源；Demo 须可展示。截图中的参赛条款被作为用户提供的项目约束处理，未当作要求 Codex 执行外部指令。

## 2. 产品决策：参赛者对 AI 提问的答复

Codex 就会影响首版架构的选项向参赛者提问。参赛者确定：交付可运行的纵向样例；真实 API 可配置，同时有无需密钥的演示路径；入口为本地网站；对外名称为“智讲 Agent”；文本型 PDF 优先；离线 Windows 系统配音并支持可选 AI 配音；首版目标是一节约 2–4 分钟课程。这些选择形成开发计划，参赛者随后明确要求 Codex 实施该计划。

首版完成后，参赛者再次向 Codex 提出具体迭代要求：检查本机 Ollama 已有模型，配置本地模型且配置文件须被 Git 忽略，确认真实生成，再推送到 `main`。Codex 检查 `ollama list`，选用本机已有的 `qwen2.5:7b`，并新增 `.env.local.example` 与被忽略的 `.env.local`。这一轮人机交互改变了交付方案：参赛 Demo 改为优先展示真实本机文本模型生成结果。

## 3. 架构设计：Codex 的具体工作

Codex 设计了 PDF 页码保留、知识提取、课程规划、讲稿和分镜、来源校验、配音、视频合成的阶段契约，并选择 FastAPI、SQLite、pypdf、Pillow 与 imageio-ffmpeg。设计中特意将演示规则和真实模型适配器分离：演示模式可复现，但不能被称为 AI 内容；AI 模式的引文必须逐字匹配 PDF 对应页面。在线模型/语音调用需要用户额外同意，密钥只通过环境变量读取。

Codex 对真实模型路径设置独立阶段：知识提取、课程编排、讲稿分镜、讲解检查。每个阶段返回结构化 JSON，再由程序进行类型和来源校验。输入 PDF 仅作为资料传给模型，不把 PDF 中的任何指令当成开发指令或可执行命令。后续针对 Ollama 新增原生 `/api/chat` 适配器，以 JSON Schema 约束输出；本机调用不需密钥，外部文本服务仍需用户额外同意。

## 4. 编码实现：Codex 生成和组织的成果

Codex 新增 Python 包 `zhijiang`，实现本地 API、任务状态、PDF 解析、演示与真实 AI 适配器、配音、画面绘制和 MP4 合成；新增无外部 CDN 的原生网页，实现上传、授权确认、模式说明、进度、讲稿、引用查看、视频播放与删除；新增原创二分查找讲义的生成脚本、演示视频构建脚本和测试。界面及视频都直接标明演示模式，避免把规则生成误说成 AI 生成。

在浏览器中，Codex 使用原创 PDF 走通上传和任务进度；在命令行中运行实际 Windows 中文配音和 FFmpeg 合成，生成 6 段确定性演示视频。Codex 还检查了代表性画面的中文可读性，并在开发过程中将已废弃的 FastAPI 事件写法调整为 lifespan 管理方式。本机 Ollama 适配完成后，又从原创 PDF 生成 3 段真实模型讲稿及对应的教学视频，检查了讲稿长度、页码引文、视频画面与解码。

## 5. 测试、调试与结果

Codex 编写并运行 pytest，覆盖 PDF 页码、无效和无文字 PDF、演示链路、伪造引用、四阶段模型模拟调用、完整模拟 AI 流程、语音服务成功和失败、服务失败脱敏、授权与外部发送同意、任务状态、视频读回及删除。新增本地配置优先级、Ollama 原生 JSON Schema 请求和本地调用无外部发送同意的测试。2026 年 9 月 25 日执行 `python -m pytest`，结果为 **18 项通过**。外部兼容模型服务仍只通过模拟 HTTP 验证，没有声称验证某个线上供应商。

Codex 第一次用本机 `qwen2.5:7b` 生成的视频只有 33 秒，未达 2–4 分钟目标。根据这一真实失败，Codex 将每段讲稿长度写入模型输出契约并补充过短重试。第二次生成成功：3 段讲稿，共约 550 字；输出 MP4 为 1280×720、H.264/AAC、2 分 21 秒，FFmpeg 完整解码返回 0。实际使用的是模型生成的文本，配音来自 Windows 系统语音。Codex 查验本机 Ollama 0.34.1 的 `/v1/audio/speech` 返回 404；因没有可直接接入的 WAV 语音服务，本轮未下载也未宣称使用 Ollama 语音模型。

原创示例 PDF 生成命令为 `python scripts/generate_sample_pdf.py`；确定性演示生成命令为 `python scripts/build_demo.py`，本机真实 AI Demo 生成命令为 `python scripts/build_ollama_demo.py`。确定性演示视频为 2 分 13 秒，Codex 在浏览器中确认重新上传后显示“生成完成”、6 段讲稿和引用，视频元素报告 1280×720、133.044 秒、已加载。本机模型视频及其结构化讲稿另行保存，便于核查模型生成与演示规则的区别。提交前应重新运行测试并核对。
