# Git 隐私与产物管理

## 保留与排除

版本库保留代码、测试、空配置模板、原创教材输入、素材源码、来源清单和文字说明。`examples/binary_search_original.pdf` 是公开原创输入与测试夹具，属于明确白名单；它不是用户上传资料或课程结果。

`.gitignore` 排除本地 `.env*`、凭据文件、私钥、环境与缓存、上传资料、任务数据库、模型权重、课件/视频/音频/课程 JSON、PDF/ZIP 导出和生成截图。标准结果目录为 `data/`、`output/`、`demo/`、`submission/`、`tmp/`、`dist/`，自定义生成目录也应放在这些目录内。

本轮从索引移除了 12 个已经被跟踪的文件：4 个旧 Demo/课程 JSON、参考输入 `docs/XZB2.pdf`、2 个输出截图、5 个历史 PDF/ZIP。每个本地文件都保留，后续修改不进入普通提交。添加 `.gitignore` 本身不会自动取消已有文件的跟踪。

## 推送前检查

```powershell
git config core.hooksPath .githooks
.\.venv\Scripts\python scripts\check_git_privacy.py
```

本仓库启用了 `.githooks/pre-push`；每个新克隆需执行一次上述 Git 配置。默认命令检查暂存内容。普通 `git push` 会检查实际待推送的最终与中间提交，因此“先提交密钥，再删除”仍会被拦截。被强制加入的忽略文件也会被拦截。

凭据检测覆盖本机 `.env*` 中配置的密钥、常见提供方 token/私钥格式、带引号的非空密钥赋值，以及配置模板中的非空密钥字段。检测只打印文件名和问题类型，不输出密钥或文件内容；未完成检查则阻止推送。规则不能识别所有自定义凭据格式，源码中的凭据应使用配置引用。

历史已经推送的提交仍包含曾经跟踪的旧产物；本次正常提交不改写它们。清除远程历史需要单独规划历史重写。当前 `data/` 和 `.env.local` 未曾被 Git 跟踪；本轮还会检查可达历史中的密钥模式，不将“未匹配到”解释为所有形式的凭据都经过证明。

## 验证

测试使用临时 Git 仓库和构造的假凭据，覆盖忽略/白名单、强制加入生成物、内嵌密钥、空模板、中间提交和新建/删除分支。2026-10-11 执行隐私与 API 回归测试，50 项通过；暂存检查通过。

另扫描当时 26 个可达提交中的 665 个文件内容对象，未匹配到本机配置密钥、常见提供方密钥格式或私钥；赋值模式命中的是文档占位示例和测试假凭据。历史产物依然存在于旧提交中，本轮未改写历史。
