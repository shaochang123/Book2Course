从项目 README 拆出的详细参考；能力边界见[实现状态与路线图](实现状态与路线图.md)。历史机器版本与验证结果以链接的实测报告为准。

## 使用本机 Ollama

安装并启动 [Ollama](https://ollama.com/)，通过 `ollama list` 检查模型。默认模板使用非推理版 [`qwen3:4b-instruct`](https://ollama.com/library/qwen3%3A4b-instruct)；如果本机没有该模型，可运行 `ollama pull qwen3:4b-instruct`。安装其他模型时，在网页填写实际模型名。复制配置模板后重启 Web 服务：

```powershell
Copy-Item .env.local.example .env.local
```

`.env.local` 已加入 `.gitignore`。可在其中修改 Ollama 地址和模型名。真实 AI 模式通过 `/api/chat` 生成知识点、课程规划和讲稿；本机地址配合本机执行的模型时提取文本留在本机，Ollama 云模型标签仍会将资料转发到外部服务。模型先选择带页码的原文片段编号，程序再填入并核验引文，减少模型改写原文造成的错误。普通结构化调用使用 8192 上下文，数学构造调用申请 16384；通用分镜分为对象布局与操作计算两次调用，分别检查并修正。CPU 推理和复杂分镜可能耗时较长。小模型可能多次修正或无法通过检查，可在网页切换更强的模型 API。

此前说明记录的环境为 Ollama 0.35.1 和 512 MiB 提示缓存；这是历史机器配置，不是当前安装要求。实际模型与服务版本以 `ollama list`、`ollama --version` 和各次验证报告为准。低内存电脑可在启动 Ollama 前设置其 llama.cpp 后端的[提示缓存上限](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)。先退出已有 Ollama 服务，再在终端启动：

```powershell
$env:LLAMA_ARG_CACHE_RAM = "512"
ollama serve
```

该设置取决于所用后端版本，重启服务后生效。暂态 HTTP 429、502、503、504 至多两次退避重试；认证错误不重试。聊天解析器返回 HTTP 500 时，使用相同契约调用 Ollama 原生[生成接口](https://docs.ollama.com/api/generate)。格式恢复与服务重试分别计数，只移除完整、有效 JSON 对象后重复的结束符，后续来源与含义核对仍须通过。持续失败会保留进度并报告错误。

失败任务可调整页面中的生成方式、文本/语音 API、音色、提示词和动画模式，再点击“使用原 PDF 重新生成”；重试采用当前设置，无需再次上传。更换外部服务地址需重新确认发送许可并提供对应密钥，旧地址的任务密钥不会传给新地址。

可通过 `/?job=任务编号` 在本机重新打开任务进度与产物，任务编号为接口返回的 32 位标识。

失败重试保留已完成的 PDF 解析、知识点提取和通过逐项审稿的分镜。来源匹配后的结构草稿保存在 `source-structure-XX.json`，口播失败可续做；这类草稿仍未获批准，复用后必须完成逐项含义审稿。独立原文理解草稿保存在 `source-reading-XX.json`，复用草稿后仍须逐项审稿，不把缓存当作批准。复用分镜时重新核查来源与执行规则，随后重新配音和渲染；未通过的候选不进入缓存。更换 PDF、模型地址、模型或提示词时自动使相关分析缓存失效；缓存不含 API 密钥。知识点编号受当前原文批次的输出契约约束；提取保留定义和条件的上下文，排除多列计数表头。候选方案和拒绝原因保存在任务目录的 `knowledge-planning.json`、`teaching-design-XX.json`；`model-calls.json` 记录本机调用耗时、token 数和输出终止原因，便于定位失败阶段。

基础模式讲稿中的具体数字须出现在对应原文摘录中；否则要求重写，仍不符合时删去相关句子或要点并提示复核。专用推演和通用场景允许标明条件的原创教学参数及计算结果，不受这个原文数字过滤器误删；原理引文和补充算例分别标注。数值关系检查不证明自由口播、领域事实或教学解释完全正确。

可计算几何分镜的自由口播描述对象、操作和原因，具体数值由已核验参数与计算结果生成。程序拒绝未绑定的字面数字及常见中文数值断言，避免审稿模型放过错误计算口播。每个新片段规划 3–5 步，每步定性口播 12–100 字符，以短步骤组织连续讲解；旧课程数据仍可读取。原始模型草稿仍保留；定性解释与领域事实继续需要来源和人工核查。

也可以不创建 `.env.local`，直接在网页选择真实 AI 模式并填写本次任务的 API 配置。API 密钥仅在任务运行期间留在服务进程内存，不写入 SQLite、课程 JSON 或网页响应；刷新页面或服务重启后重试外部模型任务，需要重新输入密钥。自定义提示词作用于课程规划、教学参数和基础讲稿风格；首轮数学口播由核验模板生成，提示词不能绕过来源与计算核验。

已生成的[示例视频](../demo/zhijiang_ollama_demo.mp4)与[讲稿及来源](../demo/zhijiang_ollama_lesson.json)可直接查看。示例视频的讲稿由本机模型生成，声音来自 Windows 系统语音。

## 整本扫描教材的进度与续跑

扫描页逐页显示解析/OCR 进度并保存 `parsed-pages/page-XXXXX.json`，包括已处理的空白页。知识点按原文批次显示进度，核验通过后立即保存 `knowledge-batches/batch-XXXX.json`。失败后使用原 PDF 重试可复用已完成页面和批次；更改原 PDF 或对应分析设置会使相关缓存失效。以前完成的整份解析缓存也可复用，无需重新 OCR。

本机 Ollama 使用流式响应显示当前调用耗时与已收到字符数；读取材料、尚未返回正文时也更新耗时。完整响应和完成标记都收到后才核验、保存结果，不把部分 JSON 当成成功。CPU 上处理整本教材仍可能耗时较长；网页百分比表示阶段进度，不是预计剩余时间。可以关闭或刷新网页，通过任务链接继续查看，但本机服务须保持运行。

中文扫描摘录保留短定义、换行与相邻语境，排除明确版权/编者说明/目录页；判断题保留题目说明。知识摘要拒绝补入当前引文没有的数值，不能猜测 OCR 缺失的分数与比例。原创教学算例在后续场景中另行标记与核验。文字匹配及数字检查仍不能证明 OCR、题目解答或全章覆盖正确。

实际六年级扫描教材的诊断、测试与续跑状态见[长教材进度验证](long-textbook-progress.md)。

一个知识点未通过数值检查时，只修正该条目的解释，保持已通过条目的标题、类型、解释和来源不变，也不删掉出错主题来凑成功。未批准的批次草稿保存为 `batch-XXXX.draft.json`，重试继续修正后再核验；它不是已完成的知识点缓存。持续失败时报告具体知识点，保留草稿与修正记录，便于核对原文。

自由改写持续失败时，模型只能为该知识点选择当前摘录中可读的说明句编号，程序逐字填入原句；候选句不含具体数值或分数，且必须属于该知识点的来源。短摘录缺少可用说明时，再从同一原页选择有依据的原文片段编号，更新该出错条目的引文并重新生成定性说明；同页引用须通过连续文字匹配，旧缓存也重新检查。没有可用候选或选择不匹配时明确报错。这种受限修复保留主题，不猜补损坏的 OCR，也不等于已恢复缺失公式。

数字相同不代表分数、比例和公式正确。知识摘要中的定量分句必须逐字保留当前摘录；否则定向修正为可读的定性概念，并提示核对原图。检查包含中文分数和常见数值断言，区分“一个数”“两个数”等泛指表达，以及原文已有的 `CO2`、`H2O`、`B12` 等名称。旧批次仍按当前规则复核；通过条目不重写。这些文字规则不能证明任意领域事实或完整教学含义。

本机 Ollama 的原生 Schema 解码中断时，任务尝试普通 JSON 解码，并继续按完整数据契约验证；该格式恢复最多三次调用，格式合格不等于内容通过。成功的兼容方式在当前任务的同类阶段复用，记录于 `model-calls.json`。来源事实的解码正则有长度上限，程序可只补齐缺失的句末标点；短片段、截断运算符、错误编号和非中文说明仍被拒绝。

扫描页进入分镜前，独立来源事实也复核数值引用。无法逐字绑定的数值推断不进入事实数组，拒绝记录保存在 `source-reading-XX.json` 的 `rejected_facts`；课程知识点仍保留，已有可读定义和条件继续用于讲解。没有可核验事实时明确报错。此检查不恢复 OCR 缺失数值，也不取代逐项语义审稿与原图核对。

定性图示默认讲解来源事实，只有提示词明确请求生活例子或类比时才开放新增类比；原文已有示例时优先保留。数值示例须进入计算核验的场景，不能借生活类比补写未经核验的分数或测量值。

扫描页中尚未作答的数量问题保留在原页供核对，不作为已成立的事实口播；即使数字出现在 OCR 中，分数版式也可能丢失。重试时重新检查事实草稿，剔除被拒绝的可选断言并记录原因，其余可读事实继续复用。

模型的 OCR 事实草稿全部被数值检查拒绝时，可从当前片段选择可读的原文说明句编号，程序逐字填入，修复记录见 `source-reading-XX.json/repairs`；没有可用句子仍报错，原文含义审查继续执行。对象候选支持数量短语和动作短语，不要求所有知识都能被词性标注为名词。连线保留原文的完整谓词，包括“乘”“是”等单字谓词；并列词不构成关系。显示名称在同一引文中明确出现时，程序将 `source_term` 绑定到该原文名称，并记录 `literal_node_name`，避免误选附近数字；翻译和语义仍须审查。

来源事实先检查完整 JSON 容器、条数和来源编号，再逐条检查完整中文句子、长度与数值依据；坏条目单独拒绝并记录，其余可用事实保留。容器格式修复仍失败时，扫描页也可尝试上述原句选择；不接受损坏 JSON 的局部正文，也不把连接或超时错误当成内容修复。

含义审查按表达方式核对节点：原页标注和比较图可标注短语、动作、条件或结果，不要求每项都是独立实体；不为没有连线的标注推断关系。关系和过程图的连线仍须分别核对原文依据，错误指代和口播中遗漏的条件会被拒绝。

审稿输出先记录每项的原文含义与理由，再给出支持判断；程序检查条目是否完整并汇总批准结果。原页标注使用独立的 `annotation_checks`，避免误当关系图实体。原始 OCR 与排版疑点记入 `source_warnings`；疑点使当前讲解无法确认时，该条目仍必须被拒绝。已有缓存中的拒绝不会自动改为批准。当前问题来自分镜，不能误用同页另一道练习替代。

完整课程顺序保存到 `course-order.json`，分镜失败后重试可复用；来源、知识点、提示词、模型或 API 地址变化会使该缓存失效，遗漏或重复编号不能复用。原页图片按 PDF 与图片文件的哈希核对后复用；网页显示正在导出或复用的页数，图片缺失或损坏时重新导出对应页。

## 使用本机 AI 配音

参考声线使用独立环境中的 Qwen3-TTS，详见[本机自然讲解配音](自然讲解配音.md)。当前配置模板默认给出 Qwen 模型、参考声线别名及网页 AI 配音偏好。下面的 Kokoro 是另一个轻量选择，需要显式修改模型和音色；两个语音服务使用同一端口，启动其中一个即可。

本机无 NVIDIA 显卡时，可通过 CPU 运行支持中文的 [Kokoro-82M v1.1-zh](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)。在项目目录安装可选依赖并下载 [ONNX Community 的量化模型](https://modelscope.cn/models/onnx-community/Kokoro-82M-v1.1-zh-ONNX)及 4 种中文音色（约 130 MB，保存在忽略提交的 `data/models/kokoro/`，下载脚本会校验 SHA-256）：

```powershell
.\.venv\Scripts\python -m pip install -e ".[local-tts]"
.\.venv\Scripts\python scripts\download_local_tts.py
```

在一个终端启动本机语音 API，并保持运行：

```powershell
.\.venv\Scripts\python -m uvicorn zhijiang.local_tts:app --host 127.0.0.1 --port 8766
```

在另一个终端启动主 Web 服务。使用 Kokoro 时，在 `.env.local` 或网页填写 `http://127.0.0.1:8766/v1`、模型 `kokoro-82m-v1.1-zh` 和中文音色 `zf_001`；还可选择 `zf_002`、`zm_009`、`zm_010`。本机接口无需 API 密钥，语音合成在本机进行；首次请求需加载模型，长讲稿在 CPU 上需要更多时间。可打开 [语音服务健康检查](http://127.0.0.1:8766/health)确认模型文件已安装。

## 外部模型与语音服务

如需使用外部文本模型，在启动服务前设置兼容 `POST /chat/completions` 的服务地址、模型名和密钥：

```powershell
$env:ZHIJIANG_LLM_PROVIDER = "openai"
$env:ZHIJIANG_LLM_BASE_URL = "https://你的服务地址/v1"
$env:ZHIJIANG_LLM_API_KEY = "你的密钥"
$env:ZHIJIANG_LLM_MODEL = "你的模型名"
```

外部 AI 配音需要兼容 `POST /audio/speech` 并能返回 WAV。以下变量可替换 `.env.local` 中的本机语音配置；也可在网页为单次任务填写：

```powershell
$env:ZHIJIANG_TTS_BASE_URL = "https://你的语音服务地址/v1"
$env:ZHIJIANG_TTS_API_KEY = "你的语音密钥"
$env:ZHIJIANG_TTS_MODEL = "你的语音模型名"
$env:ZHIJIANG_TTS_VOICE = "alloy"
```

使用外部服务时，网页会要求额外确认发送提取文本或讲稿。语音和文本 API 密钥仅在任务运行期间保留在服务进程内存；失败后重试外部语音任务需要重新输入语音密钥。不要将密钥提交到仓库。

## 通用数学对象模式

`geometry` 仅用于真实 AI，要求 TeX 和通用动画依赖；从完整引用页规划二维对象、函数曲线和参数曲线，不用流程图、原页高亮或要点淡入替代数学操作。对象表达式须绑定已声明参数，步骤使用受限参数变更；SVG 与视频共享等单位坐标。模型仍可能无法通过检查，成功执行也需核对数学条件和画面。原页视觉识别仍可能错读复杂公式或图形。历史失败资料与结果见[数学验证](math-level-validation-2026-10.md)。

此模式要求支持图像输入的生成模型，先对照原页转录/复核公式，再规划构造图和讲解操作。普通文字 OCR 不作为复杂公式的唯一依据。网页数学对象模式使用 JSON 解码，完整 Schema 仍随任务提供，返回后检查完整结构、变量和来源；数学调用申请 16K 上下文。数学来源关系绑定实际对象，在规划采样及视频逐帧测量，可见点及标签锚点越界会拒绝。阶数与分割数等离散量不能作连续控制参数，逐项构建有限展开使用各项权重。

网页可分别填写“数学规划模型”和“独立数学复核模型”，调用同一 API 地址上的模型。支持图像的生成模型负责原页识别、来源清单和 SVG 画面审查；规划模型负责设计、对象构造与讲解操作；复核模型独立检查文字及实际覆盖。来源清单先由不同的规划模型核对含义；规划与生成使用同一模型时改用复核模型，只有一个模型时仍是自查。两个可选字段留空时使用生成模型。API 表单字段为 `llm_math_model`、`llm_review_model`，只作用于当前任务；场景 `model_roles` 记录实际职责。数学规划调用与格式错误单独保存在 `mathematical-planning-calls.json` 和 `mathematical-planning-format-errors.json`。独立复核应选与规划不同的模型，不把候选自查当独立审稿；复核仍不是正确性证明。

原页转录保留原文语言、数学条件与实际图示；英文文字页转录缺少大部分原词时会要求重读，不能把摘要或译文当逐字引文。空白页在模型调用前被拒绝，复核可以清除不存在的图示说明。来源缓存按原页图像、原文、模型和服务地址绑定；这些规则仍不能证明转录准确。

数学对象和讲解操作分阶段输出。实际测量使用对象类型限定的工具：带符号坐标、非负距离、面积、非负夹角、有向角、函数值与导数。比例的分母也是实际对象测量。关系可要求全程成立，或只检查明确编号步骤的终点；终点结论不能冒充全程不变量。标签随动点锚定，颜色跟随对应曲线。异常函数绘图区间压缩核心动点时重新规划，不改变坐标比例来掩盖问题。

来源覆盖清单在候选规划之前独立生成，列出原页必要条件、结论和已解核心算例。模型只选择有限的 `source_ids`，程序直接填入对应原文，记录 `source_excerpts` 与 `citation_method=selected_exact_source_excerpts`；跨段事实保留多条独立出处，不要求模型重打引文或拼接成新句。编号绑定不证明含义正确，后续仍对照完整来源审查。概念照片、装饰插图允许用等价的正确数学示意解释；已解核心算例仍保留原值和条件。来源主语按对象类型、顶点数、可见步骤和测量依赖绑定，拒绝无关占位图形。数学课按来源安排 3–10 步，短而完整的中文讲解不为固定长度补字；失败清单不是教学质量批准。

`point_on_curve` 可从参数曲线或角弧计算真实测量点，辅助点可隐藏；用于端点对齐与拼接的终点关系核验。变换的原图需隐藏或设 `reference=true`，后者自动淡化并标为参照。EOF 缺少完成标记时丢弃该次正文，同一请求最多重试两次；数学字段格式最多三次恢复，仍须完整校验。

`align` 按源与目标的锚点/方向点计算旋转和平移，进度从零到一，不缩放；每帧检查进度和非退化方向。实际角弧首尾可作辅助方向点，不猜旋转角。构造错误即使同时提及目标文字也返回构造层；仅操作或措辞问题才能保留图形局部修复。持续语义构造错误最多重新设计两次，记录原稿、修订和拒绝原因。

模型输出因预算达到上限而截断时，只增加一次该阶段预算（最多 16384），仍须收到完整结束标记并通过完整契约；截断 JSON 即使能解析也不批准。数学构造最多十轮规划/修复，每轮有效构造立即进入操作与验证，第十轮也有完整验证机会。修复请求附上被拒候选及具体错误片段；缺少控制参数或持续失败的操作返回构造层。失败时保存各轮对象、操作、拒绝原因及复核结果；没有通过的候选不进入媒体生成。教学设计草稿不作为教材事实交给审稿。

选择 Ollama `:cloud` 或 `-cloud` 模型会将教材发送到云端，即使地址为 `127.0.0.1`；生成或复核任一路径为云端时，网页/API 都要求额外同意。数学模式会发送教材页图像及文本。自定义代理或不带云标签的别名须自行确认实际目的地，默认本机配置不会自动改成云模型。

可选 `ZHIJIANG_OLLAMA_NUM_GPU` 设置 GPU 层数，留空自动分配。本轮 8GB 显存机器以 `24` 留出桌面和上下文余量，不能照搬为所有机器的最优值。调用日志记录实际请求、用时、token 数与终止原因；云模型对上下文/采样参数的执行取决于供应商。已有场景必须重新核查，不能把旧模型批准或缓存当作新版本验收。

数学复测记录了 `qwen3.5:9b` 与 `qwen2.5:7b` 的实际摘要、量化和调用设置；本机 8 GB 显存在高负载时曾出现长期无输出。串行测试和记录模型变化有助于诊断，但不构成模型能力排名。不会自动改写 `.env.local` 或下载其他模型；为新任务选模型时使用已安装的文本生成模型，不能使用 embedding 模型。


数学审稿直接对照教材原图与每步 SVG，先记录来源、几何、连续操作的观察再判定批准。相邻线段可按共同端点测量顶点内角；有向角弧可保留完整扫角，并核验实际弧端点。复杂计算表达式拆为受限的派生节点，不放宽 AST 限额。数值口播仅修复出错句，保留已核验对象和操作；运动帧持续检查，静止讲解保持已核验终态。


### 来源含义、构造工具与局部修复

来源清单对照真实原页图像生成，在设计场景之前逐项核对翻译、条件、数值、基准整体及算例分类，最多三轮修复。记录保存在 `math-source-scope-attempts.json`；它仍是模型核对，需要人工对照原页。构造工具返回初态真实坐标、面积、长度及角度，再核对当前对象和自由度是否能表达来源要求。

`intersection` 支持两条直线/射线/线段或两个圆，程序计算交点并逐帧检查真实范围和归属；不支持混合线圆求交。线与射线按实际视口延伸。曲线上动点即使隐藏，也必须位于对应曲线的实际绘图区间。

完整行为响应中个别字段违反契约时，可以只修复 `operations`、`claims` 或 `roles`，保留其余有效字段并记录 `behavior_format_repairs`。只接受完整 JSON 容器，不恢复损坏 JSON 的局部正文；修复后仍执行完整契约、实际关系、来源、SVG 及运动校验。中文“分之”数值口播也须绑定真实计算。收合为零的误差线按运动采样核对，不只看终点；始终退化的线仍被拒绝。

`ZHIJIANG_OLLAMA_THINKING_LEVEL` 仅用于 `/api/show` 实际公布的字符串档位，留空沿用服务默认值。不支持的档位明确报错；布尔开关模型仍使用 `ZHIJIANG_OLLAMA_SEMANTIC_THINKING`。数学纯格式恢复最多三次；第三次首次达到输出上限时才允许额外一次扩大预算，不接受截断结果。云服务当前不支持原生结构化输出，完整 Schema 留在提示词并由程序验证，见 [Ollama 官方说明](https://docs.ollama.com/capabilities/structured-outputs)。


构造草稿最多 32 项，分割后核心对象最多 48 项，含点名的渲染契约最多 64 项。来源已核对的有效对象图可通过 `MathConstructionPatch` 局部修复：保留正确对象，补充缺失构造及真实连续控制量；依赖排序后重新编译与全量验收。两次连续操作失败返回构造层，不要求错误措辞相同；两次补丁格式/编译失败后重新生成完整构造。补丁及原图保留，不把新模型编辑当人工提供的分镜。

来源与可表达性复核按每批两项进行，汇总仍保留全部要求。已核对的中文来源清单逐字绑定到说明卡和实际配音，定义与条件在首次运动之前讲出；说明卡不能替代核心图解、算例或连续推演。时间线中的 `fact_panels` 与 `source_seconds` 记录真实语音时长，完整网页讲稿包含对应陈述。通式定义可这样说明，不能要求每条定义都有任意阶数的动态对象；实际示例仍须画对并核查。

来源主语按基本几何类型及 `count` 表示，最多六项；复合实体分解为实际必需对象，不使用编译器内部的分割 `group` 类型。绑定逐个核对数量、类型、可见性及测量依赖。缺少测量或步骤显示先修复操作，类型/对象缺失返回构造层；两次操作失败仍会升级。已给出的完整图解方案不会因没有印出算式而被省略。非有限初态在审稿前拒绝，失败候选不能进入媒体生成。

## PPT 模板与恢复

模板在网页选择，或通过创建/重试表单的 `ppt_template=classic|paper|academic|editorial` 指定，不需要额外依赖。旧任务和 API 默认 `classic`，网页新任务默认 `paper`。新模板的模型排版复用当前任务的模型与已有讲稿、短句、图形和动画；仍执行相同的外部传输同意。仅换模板不会授权新的远程服务。方案按资料内容、模型地址/名称与模板契约绑定缓存；原文、短句或模板变更不能复用旧方案，失败重试清理旧布局预览。细节见[课程导演与 PPT 模板](课程导演与PPT模板.md)。
