# 素材库与共享教学画面

更新：2026-10-10。

## 使用

网页在 PPT 模板下提供默认开启的“自动检索插画与符号”。使用真实 AI 时，本地检索先从标题、讲稿、画面短句和相关知识图谱实体找到最多八个候选，课程导演选择素材 ID、用途和逐字对应的对象锚点。每页最多一张主要配图、两个辅助符号；`main` 仅指所选素材中最大的一张，不表示画面主体。普通页面的素材区域合计不到画面面积的 8%，用 `group_id` 绑定到对应的实例或观点。标题、讲稿中没有实际对象别名的候选不会强行配图；抽象的“学习”不会自动变成铅笔。没有合适素材时保留教学图示，缺口记录在 `presentation-plan.json`。

普通页面的 `visual_groups` 按要点组织信息，可以选择中心观点、并列、对比或实例注解构图；额外画面文字只能引用本段逐字讲稿片段。插画与相关文字放在同一分组，避免每页固定位置的贴纸。对比页保留成对区域，其余讲解使用开放留白。续页仅重排仍有内容的分组，不保留空卡片。

配图规划不重写知识。确定性演示模式按关键词匹配，报告明确注明 `deterministic_demo_layout`。真实模型模式注明 `model_layout_selection`。模型失败不会转成成功演示。Ollama 页面规划使用 16K 上下文及 3072 输出预算；每六个片段的成功规划独立保存，续跑须通过输入指纹和结构校验。

页面规划和实例配图分阶段进行：先保留已核验的页面结构；普通片段存在对应实例插画但导演没有选择时，再调用只含素材 ID、对象名和分组编号的小契约。这一步也由真实模型选择，不按教材名称增加分支。页面字段错误只重试无效页面，不把整批配图清空。完成的布局草稿仍需结构及来源锚点校验，坏 JSON 不做局部拼接。

Ollama 的小批次修复及三字段配图调用使用原生 JSON Schema 约束输出，初次整批规划继续使用完整提示契约与程序校验；不以模型自称合规作为通过依据。对象别名只填写图中对象的同义名称，相关概念留在 `tags`。例如肺泡是肺的组成结构，不是整幅肺部插画的别名；复利也不是增长图的别名。英文词边界防止 `NotebookLM` 中的 `book` 被当成书本。相同对象的候选去重，优先实际查看过的插画，避免一个要点同时出现两幅重复的肺部图。

PPT 与 MP4 共用正文布局、插画位置、短句和渐进呈现。数学及几何使用原有场景视频，按比例放入模板窗口，保持连续变化；主视频每段讲稿只使用一次。封面、问题、路线和回顾仍是 PPT 的导航页，目前不会额外生成其配音。PPT 的动画播放页与正文相同画面，不在主视频重复播放。

正文最小 24 pt，标题 36–44 pt。长句和长课程拆页，不缩小或用省略号隐藏内容。来源、完整讲稿、配图身份和模式说明保留在备注与网页；正文不加品牌、技术标签和来源脚注。场景内部的必要公式、数值和条件继续保留。

能放在新页的关键句保持完整；额外逐字讲稿片段不为了占满页面而生成续页，空间不足时留在备注中。必需的已核验要点仍全部展示。

实际跨领域检查发现，正确口播仍可能被错误压缩成画面短句。新增 `caption_grounding.py`：普通 AI 片段的短句与已有讲稿的完整句子逐字匹配，未绑定时让模型只选完整句子编号，程序填入原句。句子不在逗号、分号或小数点处切开，条件与否定保留；额外补充文字也只使用完整短句，避免把“常见误解”之后的错误说法单独显示。选择失败明确报错，所有批次验证完才修改课件。连续数学场景保留原有表达。此步骤不改写口播，也不保证口播自身正确；记录保存到 `caption-grounding.json`。

配图契约按候选数量限制数组长度，只有一个候选时不允许模型填两三张相同图。同页的 ID 唯一性、用途和对应分组仍独立校验；不会把错误 ID 或重复图片静默当作成功。

## 目录与添加素材

`zhijiang/assets/visuals/` 包含 12 个领域目录、100 个原创 SVG 符号和 9 个 CC0 手绘插画。五个领域增加 `handdrawn/` 子目录，保存实际查看过的书本、西瓜、苹果、电脑、放大镜、灯泡、肺部、蝴蝶插画；两个书本条目由同一原画裁切，不能声称为两份独立原作。每级 README 介绍子目录及素材，Markdown 中的 TOML 块是唯一检索元数据来源。

添加文件时，在同目录 README 加入如下条目（同一个块可包含多个 `[[assets]]`）：

```toml
[[assets]]
id = "biology.example"
file = "example.svg"
title = "示例主体"
description = "画面里实际出现的对象、颜色和构图。"
tags = ["中文别名", "English alias"]
entity_aliases = ["正文中实际对象名", "object name"]
domain = "biology"
kind = "illustration"
style = "pencil-sketch"
usage = "适合哪种教学情境。"
limitations = "不能用该图表达的含义、尺寸或数据。"
source = "作者与来源链接；原创须注明作者。"
license = "MIT"
```

ID 在全库唯一，文件必须位于素材库内。SVG 需要独立 `viewBox`，不能包含脚本、外部对象或外部引用；也支持透明 PNG。原始颜色保留，避免改变器官、果实或对象的识别含义。示意曲线、原子、器官和电路符号只表示讨论对象，不能代替具体数学证明、解剖图或真实数据。

```powershell
.\.venv\Scripts\python scripts/index_visual_assets.py --check
.\.venv\Scripts\python scripts/index_visual_assets.py --rebuild --contact-sheet
```

生成的索引、PNG 缓存和五张总览位于 `data/visual-assets/`，被 Git 忽略。素材文件及 Markdown 随安装包发布。原始 100 个符号由 `scripts/build_original_visuals.py` 编写，沿用项目 MIT 许可；重建只覆盖该批符号及其说明，不删除手绘子目录。CC0 素材源自 [Openclipart](https://openclipart.org/share)，作者与页面在对应 README 中记录。`scripts/import_handdrawn_visuals.py` 可重新导入，原始文件哈希和书本裁切区域保存到 `data/art-research/import-provenance.json`。生成课程时只检索已安装文件，不临时联网下载。

## 接口、兼容和检查

创建与重试接口接受 `use_illustrations` 布尔值，创建默认 `true`，重试未填写时保留原值。旧规划的 `asset_refs` 缺失时按空列表读取。素材内容、描述、模板或讲稿变化会使规划缓存失效。已有任务的文件保持可访问。

任务中的 `presentation-plan.json` 保存候选、选择、锚点和素材缺口；`presentation-preview/manifest.json` 保存正文页、素材 ID 与片段；`video-timeline.json` 保存主视频片段映射。PPT 的图片同时嵌入 SVG 和透明 PNG 兼容图，同页可以有多个 SVG。预览由原生布局绘制，不是 PowerPoint 自身截图。

```powershell
.\.venv\Scripts\python -m pytest
.\.venv\Scripts\python scripts/verify_visual_assets.py --case ml
.\.venv\Scripts\python scripts/verify_visual_assets.py --case subjects
.\.venv\Scripts\python scripts/verify_visual_generalization.py
```

机器学习验收以已核对讲稿为内容基线，由真实本机模型重新规划素材和版式；两段已有连续演示作为本地场景保留。三领域验收使用新建的原创教材，经过真实模型的知识提取、课程、讲稿、审阅、配图、配音和媒体输出。运行结果位于 `data/illustration-acceptance/`；实际结果另记于验收报告。

泛化脚本另冻结四份未用于机器学习排版调试的原创短教材，覆盖放大镜、图书查找、蝴蝶发育和抽象逻辑，使用同一检索逻辑、同一模型与四种模板，不指定素材 ID。其中逻辑资料用于检查没有合适图片时是否强行添加图案。脚本使用 Windows 系统语音，明确不是 AI 配音；输出包含输入哈希、素材索引指纹、原始模型记录、PPT、MP4 和实际视频帧。短教材验证不能证明任意长教材的教学完整性或新数学动画均正确。
