# 取消生成限额验收（2026-10-11）

## 原因定位

用户截图中的“达到输出预算”来自项目按阶段写死的生成 token 限额。原机器学习任务在 `TopicSourceScope` 阶段请求 `num_predict=4096`，Ollama 记录 `eval_count=4096`、`done_reason=length`，尚未输出完整结果。该请求的输入为 `2365` token，推理开启；原错误提示要求更换模型，掩盖了应用主动截断这一事实。

旧代码还给其他阶段设置了 `512` 至 `12288` 等不同限额，数学重试最多钳制到 `16384`，流式调用推理超过十五分钟也会主动终止。本轮统一去掉这些生成限制。

## 当前行为

- 所有 Ollama 阶段、聊天/生成接口和格式恢复路径请求 `num_predict=-1`。官方将其定义为不限生成 token 数，见 [Ollama 参数说明](https://docs.ollama.com/modelfile#valid-parameters-and-values)。
- 兼容 API 不传 `max_tokens`、`max_completion_tokens` 或 `max_output_tokens`。
- 流式、非流式及兼容服务的生成读取不设置超时，也不设置推理总时长上限；连接、发送和连接池超时继续用于检测网络失败。
- `num_ctx` 默认不传，由 Ollama 服务决定；可通过忽略提交的 `.env.local` 中 `ZHIJIANG_OLLAMA_CONTEXT_TOKENS` 设置正整数，没有项目最大值。本机为 `16384`，不是所有安装的强制值。上下文窗口的内存开销及配置见 [Ollama 上下文说明](https://docs.ollama.com/context-length)。
- 用户的推理开关保留。普通语义推理沿用模型/服务采样，不再强制零温度；精确非推理选择和原有数学采样策略保留。推理采样建议的参考是 [Qwen3.5-9B 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B#best-practices)。
- 服务仍返回 `length` 时拒绝其正文，包括形式上闭合的 JSON；重新请求完整对象，持续失败明确报告服务端截断。没有通过结构、来源和含义检查的结果仍不会进入课件。

这些改动取消应用的生成限额，不扩展上游服务或模型自身的上下文容量，也不把网络失败或内容错误算作成功。
