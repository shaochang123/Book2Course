## 本机参考声线配音（2026-10-09）

本次请求为配置接近用户 NotebookLM 参考片的讲解声音。采用独立 `.venv-tts` 的 **Qwen3-TTS-12Hz-0.6B-Base**，本机 CUDA bf16 推理，语音编解码器使用 CPU float32；主网站通过本机 `8766` 服务获得完整 WAV。参考声音与讲稿没有发送至云模型。配置、参考段、模型和产物均被 Git 忽略，安装与启动见[自然讲解配音](自然讲解配音.md)。

### 实际安装与失败修正

- 固定 SDK `qwen-tts 0.1.1`、Torch/TorchAudio `2.10.0+cu128`。0.6B 模型修订为 `5d83992436eae1d760afd27aff78a71d676296fc`，主权重 SHA-256 为 `180b3b10eb1c9f1b4db7806d5475bae3071c0243c299d49926bab1da3b6946f6`；主权重和配套解码器均实际校验。官方来源和许可列于[第三方来源与许可](第三方来源与许可.md)。
- 从用户提供的参考视频第 `6.96` 秒提取 `6.7` 秒完整讲解句，参考段 SHA-256 为 `662e4fa3ba5eb32e3f81f6fcf49e21b5bd3d33a741bf5a290842dd8086a5d9e6`。本机转录核对后作为完整语音提示，声线别名 `notebook-reference`。
- 先实测 1.7B：首个配置请求超时；将编解码器改为 CPU、调整线程后可以生成，但 2.8 秒声音的纯合成仍需约 187.83 秒。CUDA int8 探针约 150.59 秒；CPU int8 达到长度限制失败，未输出音频。默认切换为 0.6B 原始浮点模型。多次尝试同时改变了配置，不能用这些时间作严格模型排名。
- 首次完整任务使用较长整段文本模式，未能在第一段完成前继续；终止本次语音进程后，任务保存失败。修正为最多 50 字、优先标点切段及模型默认增量文本模式，复用同一声音提示，重试同一任务成功。HTTP 仍返回完整 WAV，达到生成长度上限或任意片段失败均明确报错，不提供前半段作为成功结果。
- 实际请求等待配置为 900 秒；新增非阻塞健康检查，避免多分钟推理阻塞服务状态读取。SoX / FlashAttention 缺失的 SDK 提醒不影响此次 PCM 路径；没有宣称其已安装。
